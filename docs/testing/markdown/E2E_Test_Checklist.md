## 1. LINE：部屋を予約する（UC1）

- [ ] 「予約」を送ると、宿泊日の入力を促す返信が来る
- [ ] 不正な日付形式（例: `7月1日`、全角数字）→ 形式エラーで再入力を促す
- [ ] 過去日 → 「過去の日付」で再入力を促す（セッションは維持）
- [ ] 有効な未来日 → 空室状況が **料金つき**で表示される
- [ ] 部屋選択の形式（`Standard 1, Suite 1`）で複数タイプ・複数室を選べる
- [ ] 不正な部屋選択形式 → 形式エラーで再入力を促す
- [ ] 氏名入力 → 確認メッセージ（日付・部屋・氏名）が出る
- [ ] 「はい」→ 予約完了・予約番号・合計料金が表示される（複数室は合算されている）
- [ ] 満室日（在庫を使い切った日）→ 「ご用意できる部屋がありません」等が出る
- [ ] 対話の途中で「キャンセル」→ 中断し、案内が出る（予約は作られない）
- [ ] 日本語・絵文字の送受信で文字化けしない
- [ ] 返信が数秒以内に届く（LINE の reply token 期限内に応答できている）

## 2. LINE：予約をキャンセルする（UC4）

> 「本人確認」の確認には **LINE アカウント（または端末）を2つ**用意すると確実。

- [ ] 「予約キャンセル」（または「キャンセル」）→ 予約番号の入力を促す
- [ ] 自分の予約番号 → 予約内容が提示され、確認を促す
- [ ] 「はい」→ キャンセル完了。以後その予約はキャンセル済み
- [ ] 「いいえ」→ 取りやめ（予約は残る）
- [ ] 存在しない予約番号 → 「見つかりません」
- [ ] **他人（別 LINE アカウント）が他人の予約番号を入力** → 「見つかりません」（本人でないと操作不可・存在も推測させない）
- [ ] **宿泊日当日**の予約 → 「前日まで」で期限切れ拒否
- [ ] チェックイン済みの予約 → キャンセル不可
- [ ] キャンセルした部屋・日付が**空室に戻る**（同じ日を再予約できる）

## 3. 管理者フロントデスク画面（Web）

ブラウザで `GET /front` を開く。

### 3.1 ログイン
- [ ] 未ログインでアクセスするとログイン画面が出る
- [ ] 誤ったパスワード → エラー表示、ログインできない
- [ ] 正しいパスワード（`ADMIN_PASSWORD`）→ 管理画面に入れる
- [ ] ログアウトできる。ログアウト後は再度ログインが必要
- [ ] ページ再読み込み後の挙動（トークン保持/再ログインの要否）を確認

### 3.2 予約一覧
- [ ] 全予約が**予約日順**で表示される
- [ ] 検索の属性切替（予約番号 / 予約名 / 宿泊日 / 部屋番号）で絞り込める
- [ ] 見出しクリックでソート（1回目=昇順、2回目=降順、矢印表示）
- [ ] 行クリックで予約詳細が表示される

### 3.3 チェックイン（UC2）
- [ ] **本日分**の未チェックイン予約のみ表示される
- [ ] 予約番号・予約名で絞り込める
- [ ] 行の確定ボタン → 確認ダイアログ → 実行でチェックイン完了（部屋番号が返る）
- [ ] 詳細モーダルからも確定でき、確認ダイアログが挟まる
- [ ] チェックイン済みは候補から消える

### 3.4 チェックアウト（UC3）
- [ ] **宿泊中（チェックイン済み）**の予約のみ表示される
- [ ] 部屋番号で絞り込める
- [ ] 確定ボタン → 確認 → チェックアウト完了（請求額が表示される）
- [ ] チェックアウト済みは候補から消える

### 3.5 表示・UI
- [ ] サイドバーに現在日時が2行でリアルタイム表示される（時間が進む）
- [ ] スマートフォン幅でレイアウトが崩れない（サイドバーが上部に回り込む）
- [ ] 主要ブラウザ（Chrome / Edge / Safari 等）で表示・操作できる

## 4. 一気通貫（LINE ↔ 管理画面の連携）

- [ ] LINE で**本日**の予約を作成 → 管理画面の「予約一覧」と「チェックイン候補」に現れる
- [ ] 管理画面でチェックイン → LINE 予約が「チェックイン済み」、チェックアウト候補に移る

- [ ] LINE でキャンセル → 管理画面の一覧で「キャンセル済み」、当該日の在庫が戻る
- [ ] 予約→チェックイン→チェックアウトを通しで実行できる

## 6. 異常系・セキュリティ・境界

- [ ] LINE 未設定（環境変数なし）で起動 → `GET /front` は開けるが `POST /callback` は 503
- [ ] 不正な署名の Webhook → 400（署名検証で弾かれる）
- [ ] 管理者 API をトークンなしで直接叩く → 401（例: `GET /front/reservations`）
- [ ] 日付境界の確認: チェックインは宿泊日当日のみ、キャンセルは前日まで（実施日を跨いで確認できると尚良い）

## 7. 既知の注意点（テスト時に留意）

- `@app.on_event("startup")` の DeprecationWarning がログに出るが、動作には影響しない（`lifespan` 移行は別 TODO）。
- 在庫同期は単一プロセス前提。複数リクエストの同時実行では在庫の競合が理論上あり得る（[TODO.md](../../project/markdown/TODO.md) 参照）。
- No-show（当日・過去の未チェックイン予約）を片付ける導線は現状ない（[Cancel_Feature.md](../../design/markdown/Cancel_Feature.md) の残課題）。
- デモ予約の宿泊日は起動日基準（本日・翌日）。日付が変わると本日分が変化する点に注意。
